# 이미지 API 기능 검사

프론트엔드 없이 실제 HTTP 요청으로 인증과 이미지 기능을 검사한다. 현재 재현된 오류와 수정 우선순위는 [남은 작업](todo.md#이미지-api), 실행 결과는 [변경 이력](history.md)에 기록한다.

## 실행 환경과 인증 범위

- 테스트 전용 Docker 백엔드, MySQL 8.4, Redis를 사용한다. DB는 tmpfs에 생성하고 종료 시 폐기한다. 서버의 운영·개발 DB를 테스트 데이터로 변경하지 않는다.
- 이미지는 실제 개발 R2 버킷에 저장한다. 공개 HTTPS GET의 파일 바이트·Content-Type, 서명된 GET/HEAD, 삭제 후 공개 URL 404를 확인한다.
- 카카오 토큰 교환·사용자 조회·연결 해제 HTTP 응답만 `MockWebServer`가 제공한다. 실제 카카오 계정의 인가 코드와 동의 화면은 이 검사에 포함되지 않는다.
- 앱의 `GET /api/auth/login` → `POST /api/auth/signup` → 재로그인 → 토큰 갱신 API를 호출한다. 테스트에서 JWT를 직접 만들거나 회원을 DB에 직접 삽입하지 않는다.
- 초기 대학·지역 기준 데이터와 공지사항 검사를 위한 관리자 권한만 임시 DB에 설정한다. 관리자도 가입·로그인 API로 생성하고, 권한 변경 후 로그인 API로 토큰을 다시 받는다.
- 테스트용 인증 서버와 스토리지 호출 기록 코드는 `src/test`에만 있다. 운영 JAR에 포함되지 않는다. 앱 포트는 호스트의 `127.0.0.1`에만 공개하고, 테스트 제어 포트는 Docker 내부에서만 사용한다.

| 동아리 대표 사진 | 기본 이미지, 업로드·교체·초기화, 외부 회원 변경 차단, 동아리 삭제 시 파일 삭제 |

한 번의 HTTP 요청으로 끝내지 않고, 후속 조회와 저장소 상태를 함께 검사한다. 동일한 입력 검사는 매개변수화한다. 여러 도메인에 별도 시나리오를 둔 이유는 서로 다른 서비스가 업로드·삭제·트랜잭션을 처리하기 때문이다.

## 실행

```powershell
pwsh -NoProfile -File ./scripts/test-image-api.ps1 -R2EnvFile '<Git 외부의 개발 r2.env 절대 경로>'
```

환경 파일에는 기존 `IMAGE_STORAGE_*` 설정을 사용한다. 새 운영 환경변수는 필요 없다. 버킷 이름은 테스트 실행기와 앱 양쪽에서 `rhythmeet-dev`로 제한한다. `-SkipBuild`는 현재 소스의 테스트 이미지가 이미 빌드된 경우에만 사용한다.

1. Docker 테스트 이미지를 빌드한다. 기존 Gradle 테스트도 실행한다.
2. 폐기 가능한 MySQL·Redis·앱을 시작한다. 이미 실행 중인 동일 테스트 스택이 있으면 중단한다.
3. 준비 상태 확인 후 각 기능을 검사한다. 기능 요청이 실패하면 자동 재시도하지 않는다.
4. 검사에서 시도한 PUT 키만 정리한다. 기존 버킷의 키·크기·ETag가 유지되는지, 테스트 키가 남지 않았는지 확인한다.
5. `build/image-api-tests/result-<실행 ID>.json`에 비밀값 없는 결과를 저장하고 임시 컨테이너와 네트워크를 정리한다. 실패 검사가 있으면 종료 코드는 1이다.

결과 파일에는 검사명·성공 여부·API 경로·HTTP 상태·객체 개수만 기록한다. 환경 파일, 인증 헤더, 쿠키, JWT, R2 키는 기록하지 않는다. 결과 디렉터리는 Git 추적 대상이 아니다. 프로세스를 강제 종료하면 정리 단계가 완료되지 않을 수 있으므로 최종 `cleanup` 검사를 확인한다.

## 해석 시 주의할 범위

- 검증 기준은 체크아웃한 소스와 테스트 프로파일이다. OCI 배포본의 전체 기능, Nginx 업로드 제한·CORS, 실제 카카오 앱 설정까지 검증한 것으로 해석하지 않는다.
- 갤러리 `isPublic=false`는 API 목록·상세 접근만 제한한다. 현재 저장소는 공개 URL 방식이므로 URL을 아는 사용자의 직접 다운로드까지 제한하지 않는다. 비공개 파일 자체의 접근 제어가 필요하면 서명 URL 등 별도 설계가 필요하다.
- 탈퇴 후 지연되는 최종 계정·이미지 삭제 배치, 네트워크 중단 중 프로세스 종료, 동시 사진 변경은 이 검사에 포함되지 않는다.
- 형식 검사는 텍스트 파일과 빈 파일의 거부 여부를 확인한다. 모든 이미지 코덱·손상 파일·압축 해제 크기를 검증한 결과는 아니다.
